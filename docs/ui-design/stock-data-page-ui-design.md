# 个股数据页（/stock-data）UI 设计

> 范围：旧版 Web 应用个股数据页 `frontend/src/pages/StockData.tsx`（运行于 `http://localhost:8901/stock-data`）。
> 原则：页面只呈现客观公开数据，不给出建仓/加减仓/目标价/止损位等投资动作建议。
> 结构：整体布局（§二）→ 各子功能详解（§三）→ 真实示例（§四）→ 数据与降级（§五）→ 公司基本档案改版设计（§六）。
> 说明：布局依据当前源码；§四 示例值为本机接口实际返回，仅作布局演示，非荐股。

---

## 一、页面定位

- 路由 `/stock-data`，侧边栏「个股数据」；从每日复盘 / 自选 / 筛选等页点股票名即跳到此页并自动查询。
- 单列自上而下堆叠，无侧栏、无 Tab；仅「公司基本档案」的长文本（公司简介等）支持展开 / 收起（见 §六）。
- **A 股视图**（6 位数字代码）与**美 / 港股视图**（其它代码，含韩股）互斥渲染，两套结构不复用。
- 页头唯一动作是「让 AI 读这些数据」：把已取到的客观数据交给用户自己配置的 AI，页面本身不推荐标的。

## 五、数据与降级

- 主数据（估值、研报、分位、财务、公告）与各辅助块独立拉取、互不阻塞；每块单独跟踪 `loading / ok / empty / error` 四态。
- **失败出声（新版强制）**：任一数据块 API 失败时，UI 必须显式提示，不允许静默隐藏：
  - 页面顶部「数据状态条」汇总本次**获取失败 / 暂无数据**的块（含来源与错误信息，带「重试」按钮）。
  - 各失败块原位渲染「⚠ 数据获取失败，无法展示（来源：xxx · 错误）」占位卡；有数据的块照常显示。
  - 空数据（非失败）在原位提示「暂无数据（可能非交易时段或该股无此数据，来源：xxx）」。
- **空判定细节**：
  - [R] 板块归属·概念：`boards` 或 `concept_tags` 任一非空即视为有数据（避免误报）。
  - [P] 龙虎榜：近 30 日无上榜记录属正常"暂无数据"，不是失败。
  - [O] 资金面·筹码：`fund-flow` 接口异常（如 502）时标"获取失败"，其余子源（融资融券/股东户数/分红/大宗交易）独立跟踪。
- **数据源降级**：
  - 主力资金流：东财 push2his 不可达时，自动降级到 tushare `moneyflow`（近 120 日）。
  - 限售解禁：东财 datacenter 无数据时，自动降级到 tushare `share_float`（历史记录）。
  - 投资者互动：深市走巨潮 cninfo 互动易；沪市（6/9/5 开头）走 akshare `stock_sns_sseinfo`（上证e互动）。
  - 降级对前端透明，状态条仅显示最终结果。
- 加载中显示「加载中…」；字段级取不到显示「—」，不用旧值冒充。
- 涨红跌绿（沿用 A 股惯例）；金额、市值统一格式化后再展示。
- 页面数据存本地，AI 结论由用户接入的模型生成，本地不上传。

### 数据源降级策略

当主数据源不可用时，系统自动降级到备用源：

| 数据项 | 主源 | 降级源 | 说明 |
|--------|------|--------|------|
| 主力资金流 | 东财 push2his | tushare moneyflow | push2his 在部分网络环境被拦截，降级到 tushare 获取近 120 日资金流数据 |
| 限售解禁 | 东财 datacenter | tushare share_float | 东财无数据时降级到 tushare 获取历史解禁记录 |
| 公司基本档案 | 东财 push2 | tushare stock_company + 东财 F10 | push2 不可达时，先用 tushare 获取名片信息，再用东财 F10 补充缺失字段 |

降级逻辑在 `backend/astock.py` 中实现，对前端透明。状态条仅显示最终结果（成功/失败/暂无数据），不暴露降级过程。

## 六、[G] 公司基本档案 · 改版布局设计（草案，待确认）

> 目的：现有 [G] 只回答「什么行业、多大盘子」，缺「这家公司做什么」。本版补上**公司名片 + 公司简介 + 主营业务 + 经营范围**的叙述层。
> 数据来源：档案指标沿用东财；名片与文本优先 tushare `stock_company`，未收录（典型：新上市股票）时用东财 F10 `RPT_F10_BASIC_ORGINFO` 补齐（字段级合并）。
> 状态：**已实现**。默认收起；主营业务 / 经营范围并排；公司名片保留全部字段。

### 6.1 设计目标

- 一个卡片内分三层：**档案指标（数字）→ 公司名片（工商事实）→ 文本层（公司介绍 / 主营 / 经营范围）**，由浅入深。
- 长文本不撑爆卡片：默认截断，超出才出现「展开 / 收起」。
- 取不到就隐藏对应部分，不编值、不留空壳。

### 6.4 交互

- **默认收起**：公司简介 `line-clamp-3`、主营业务 / 经营范围 `line-clamp-2`。
- 文本超出默认行数时才显示「展开 ▾ / 收起 ▴」；不足则不显示。
- 展开状态不持久化：切换股票重置为默认收起。
- 文本按纯文本转义渲染，不解析 Markdown / HTML。

### 6.5 显示条件与降级

- 档案指标有值，或名片 / 文本任一有值 → 整卡渲染；全空则不渲染（沿用现状）。
- 名片与文本：优先 tushare `stock_company`，为空则东财 F10 补齐；两者皆无时只隐藏该部分，档案指标照常显示。
- 东财 F10 字段映射：`ORG_NAME→公司全称`、`REG_NUM→统一社会信用代码`、`CHAIRMAN→董事长`、`PRESIDENT→总经理`、`SECRETARY→董秘`、`REG_CAPITAL→注册资本`、`FOUND_DATE→成立日期`、`EMP_NUM→员工`、`ORG_PROFILE→公司简介`、`MAIN_BUSINESS→主营业务`、`BUSINESS_SCOPE→经营范围`、`ORG_WEB/ORG_EMAIL→官网/邮箱`（`ADDRESS` 可能为空）。
- 单个字段缺失（如无邮箱）→ 该键值行不显示，不用「—」占位刷屏。
- tushare 单位换算在取数层完成，原始值保留在证据中；前端只做展示格式化。
