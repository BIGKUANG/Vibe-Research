# 股票筛选页（/screener）页面布局设计

> 范围：旧版 Web 应用（`frontend/` + `backend/`，运行于 `http://localhost:8901`），在左侧导航「自选股」下方新增「股票筛选」入口。
> 数据来源参考：`a-stock-data/SKILL.md`（A股全栈数据工具包 v3.6.1，十层 47 端点）+ `docs/full-market-snapshot.md`（腾讯批量 + 巨潮代码表全市场快照方案）。
> 原则：只呈现客观公开数据与筛选结果，**不出现建仓/加减仓/目标价/止损位等任何投资动作建议**；所有派生比率/倍数经 `calc/` 计算，前端不手搓公式。
> 状态：2026-10-25 已按本文实现（财报卡片 + `/api/screener/financials` + 结果表四列）。
> 新增：另设独立「ETF 筛选」页（`/etf-screener`，侧边栏位于「股票筛选」下方），设计见 [etf-screener-page-ui-design.md](etf-screener-page-ui-design.md)。
> 更新（2026-10-25）：在「行情」卡片**前面**新增「财报」筛选卡片，指标为营收同比、净利同比、ROE、销售毛利率；ROE 由原「估值」卡片迁入本卡片。详见 §3.1、§3.6、§4.1、§4.2、§5.2。

## 一、定位与设计目标

「股票筛选」= 给全市场 A 股做**条件过滤 + 排序 + 结果导出**的工作台，和「自选股」（已确定标的的跟踪）互补，也和「板块中心」（行业级视角）互补。

设计目标按优先级：

1. **快**：默认只加载一层「全市场实时快照」，条件过滤与排序在浏览器本地完成，交互无网络等待（全市场约 5500 只 A 股，一次拉取即可，见 §四）。
2. **稳**：全市场快照只走腾讯批量（不封 IP）；财报四项（营收同比/净利同比/ROE/毛利率）走东财业绩报表**一次全市场分页拉取**（不逐只请求、6h 缓存）。东财逐只系（资金流/龙虎榜等）本期不接入，留待后续扩展。
3. **省**：一层数据本地静态表（代码/名称/行业/地区/板块/上市日）已有，零网络成本。
4. **合规**：结果表只是数据，不出现买卖信号；情绪类（涨停/热榜）显式标注「情绪参考，不进核心结论」。

## 二、导航与入口

### 2.1 侧边栏插入位置

现有顺序（`frontend/src/components/layout/Layout.tsx:22-33`）：

```
每日复盘 → 资讯雷达 → 板块中心 → 个股数据 → 多空辩论 → 自选股 → 我的持仓 → 我的研报 → 研究记录 → 接入 AI
```

改为在「自选股」**下方**插入一条：

```ts
{ to: "/screener", icon: SlidersHorizontal, label: "股票筛选" },   // 紧随自选股
```

- 图标：`lucide-react` 的 `SlidersHorizontal`（多条件过滤语义，和个股数据的 `Search` 区分开）。
- 路由：`frontend/src/router.tsx` 增加 `{ path: "/screener", element: <Screener /> }`。
- 折叠态（`collapsed`）沿用现有 `title` 悬浮提示逻辑，无需特殊处理。

### 2.2 页面版式与容器宽度

筛选页采用**上下布局**：上半屏是筛选条件区（可折叠），下半屏是结果列表，整体单列、自上而下。不含左侧固定筛选栏。

现有 `<main>` 内容区是 `max-w-6xl`（`Layout.tsx:174`）。结果表列较多（默认 19 列），`max-w-6xl`（1152px）偏窄。建议二选一：

- **方案 A（推荐，改动小）**：给 `Layout` 的 `main` 内层容器按路由放宽 —— 当 `pathname === "/screener"` 时用 `max-w-[1600px]`，其余保持 `max-w-6xl`。
- **方案 B**：筛选页内部对结果表做横向滚动，表体用 `min-w-[1100px]` 包裹，筛选区仍铺满容器宽度。

上下布局的好处：筛选区宽度充裕，条件组可横向平铺成多列卡片，不必挤在窄侧栏里滚动；结果表也能占满整屏宽度。

- **「更多条件」小组件本期不做**（一致预期/资金筹码/技术形态/事件情绪等深度条件暂不进入页面，设计方案保留在 `§4.3 后续扩展条件`）。

### 3.4 排版原则（简洁美观）

1. **一屏两段，主次分明**：上半屏是「输入」（筛选条件），下半屏是「输出」（结果列表）；视觉重心落在结果表，筛选区永远不与结果表抢焦点。
2. **数字优先、去噪**：所有数字列用等宽字体（`font-mono`）+ `tabular-nums` + 右对齐，读表像看行情软件一样对齐；涨跌只用红/绿两种颜色，其余标签一律中性灰，避免整屏花。
3. **留白成节奏**：沿用现有 8px 间距体系（`gap-3` / `mb-4` / `p-4`），卡片之间固定 12px，区块之间 16–24px，不靠分割线堆砌。
4. **沿用现有设计语言**：容器统一用 `GlassCard`（`glass` 玻璃拟态：半透明填充 + 发丝边框 + 顶部内高光），主色沿用暖橙 `--primary`；不引入新色板、新圆角、新阴影。
5. **交互反馈轻量**：悬停才出现的行内操作、输入聚焦时边框转主色、加载用骨架条而非转圈，保持画面安静。
6. **克制用色**：主色只用于「选中态 / 焦点 / 可点强调」，面积小；大面积是 `background` / `card` / `muted` 的中性层次。

### 3.5 栅格与间距

| 区域 | 规范 |
|------|------|
| 页面容器 | 沿用 `Layout` 的 `px-6 py-6`，筛选页放宽到 `max-w-[1600px]`（见 §2.2） |
| 页头 | `PageHeader` 默认，`mb-6` |
| 筛选卡容器 | `GlassCard` + `p-4`（比默认 `p-5` 略紧，提高信息密度），`mb-4` |
| 筛选卡栅格 | CSS `grid grid-cols-12 gap-3`：市场板块 / 行业 / 估值 / 市值范围 各 `col-span-3`；财报整行 `col-span-12`，内部 4 个区间 `grid-cols-4` 等分；行情整行 `col-span-12`，内部 5 个区间横向 `flex gap-3` 等分 |
| 结果卡容器 | `GlassCard` + `p-0`（内部工具条与表格自带内边距），与筛选卡间隔 `mb-4` |
| 表格单元格 | 左右 `px-3`，行高 `h-10`，表头 `h-9` |

响应式（`§3.9` 详列）：`≥1440` 四卡一行 → `1024–1440` 两卡一行 → `<1024` 单列。

### 3.6 筛选区视觉规范

- **卡片标题**：`text-xs font-medium text-muted-foreground`，前缀一个 3px 高、`bg-primary/70` 的圆角竖条（或用 14px 线性图标），标题与内容间距 `mb-2.5`。
- **输入控件**：统一高度 `h-8`，`rounded-md border border-border bg-black/20 px-2.5 text-sm outline-none transition-colors focus:border-primary/50`（与自选股页 textarea 同款）。
- **区间输入**：`[min] – [max]`，两个 `input` 各 `w-20 text-right font-mono`，中间用 `text-muted-foreground` 的「–」分隔；空值显示占位符「不限」（`placeholder:text-muted-foreground/40`）。
- **快捷档位 chips**：`rounded-full border border-border/60 px-2.5 py-1 text-xs`；悬停 `hover:border-primary/40 hover:text-foreground`；选中 `border-primary/50 bg-primary/10 text-primary`。市值档位一行 5 个，超出换行。
- **财报卡片（新增，位于行情上方）**：
  - 结构：`col-span-12`；内部 `grid grid-cols-1 gap-2 sm:grid-cols-2 xl:grid-cols-4`，四列依次为「营收同比% / 净利同比% / ROE(%) / 毛利率(%)」，每列纵向为 `标签 + RangeInput + 快捷 chips`。
  - 标题：`财报`，右侧跟随报告期徽标（`rounded bg-muted/50 px-1.5 py-0.5 text-[11px] font-mono text-muted-foreground`，如 `2026Q3`）与口径说明 `累计口径`（`text-[11px] text-muted-foreground/60`）。报告期未获取时徽标显示 `报告期未获取` 并转 `text-warning`。
  - 快捷档位（点击即填入区间，再点取消）：
    | 指标 | 预设 chips |
    |---|---|
    | 营收同比% | `≥20` / `≥0` / `↓20`（≤ -20） |
    | 净利同比% | `≥20` / `≥0` / `↓20` |
    | ROE(%) | `≥15` / `≥8` / `≥0` |
    | 毛利率(%) | `≥40` / `≥20` / `≥0` |
  - 底部一行（`flex items-center justify-between`，`mt-2 border-t border-border/40 pt-2`）：左「仅显示已披露财报」toggle（默认开）；右 `text-[11px] text-muted-foreground/60` 显示「数据 HH:MM 更新」或「财报数据加载中…」。
  - 财报数据未就绪时：四个 RangeInput 与快捷 chips 置 `disabled`（`opacity-50 cursor-not-allowed`），卡片保留占位不塌陷；不静默把「无财报数据」当成「不满足条件」。
- **多选标签**：已选项为 `rounded-full bg-primary/10 px-2 py-0.5 text-xs text-primary`，尾部 `×` 按钮；下方是搜索框 + 复选列表（最多 `max-h-40 overflow-auto`）。
- **开关**：排除 ST / 仅正 PE / 排除僵尸报价 / 仅显示已披露财报，沿用现有 toggle 风格，右侧贴齐。
- **操作栏（筛选卡底部，右对齐）**：
  - **开始筛选**（主按钮）：`inline-flex h-9 items-center gap-1.5 rounded-lg bg-primary/15 px-5 text-sm font-medium text-primary shadow-glow transition-colors hover:bg-primary/25 disabled:opacity-40`。点击后提交草稿条件 → 应用过滤 → 把结果表滚到顶部；**筛选区保持展开，不自动折叠**（是否收起由用户点头部「收起」自行决定）。
  - **重置**（次按钮）：`h-9 rounded-lg border border-border/60 px-4 text-sm text-muted-foreground transition-colors hover:border-border hover:text-foreground`。一键清空所有条件回到默认（默认开关保持：排除僵尸=开、排除 ST=开），并立即重新筛选。
  - 两按钮间距 `gap-3`，与上方卡片间距 `mt-3`；筛选卡头部右侧显示「已选 N 项」与「收起/展开」图标按钮（`ChevronUp / ChevronDown`，`text-muted-foreground hover:text-foreground`）。
- **收起态**：筛选卡收成一行「已选条件摘要」（每条件一个中性 chip，未选显示「未设置条件」）+ 右侧「展开筛选」。摘要行 `h-12`，把纵向空间让给结果表：

### 3.7 结果区视觉规范

- **工具条**（表格上方一行，`flex items-center justify-between`）：

## 四、数据分层与筛选维度

### 4.1 三层数据架构

```
L0 本地静态表  frontend/src/data/stock_codes.csv（code,name,industry,area,market,list_date）
               A股 5562 只（主板2278/中小板919/创业板1406/科创板616/北交所343），零网络
        ↓
L1 全市场实时快照  GET /api/screener/snapshot（后端内存缓存，腾讯 qt.gtimg 批量，≤500 只/块）
               ~5500 行 × 20 列，2 秒级；不封 IP
        ↓（与 L1 并行，一次全市场拉取）
L1.5 全市场财报快照  GET /api/screener/financials（东财业绩报表 stock_yjbb_em，单次约 24 页）
               按报告期返回 {revenue_yoy, profit_yoy, roe, gross_margin}，内存缓存 6h
        ↓（前端按 code 合并 L1 + L1.5，本地过滤）
L2 其它增强（本期不做）  一致预期(同花顺) / 个股资金流(东财) / 板块归属(东财) / 龙虎榜·解禁·两融(东财)
        ↓
L3 市场级榜单 行业排名(现有 /api/industry) / 板块资金流(§3.8) / 涨停四池(§8.1) / 热榜人气榜(§10.2)
```

**核心判断：筛选的「主力维度」放在 L1 + L1.5**。L1 腾讯批量快照零鉴权、不封 IP、覆盖全市场，提供价格/涨跌/换手/量比/振幅/PE/PB/市值/成交额/涨跌停/证券类型；L1.5 用东财「业绩报表」**一次拉全市场一个报告期**（东财 data-center 分页接口，实测约 7 秒、1.1 万行，含营收同比、净利同比、ROE、销售毛利率），因此不需要像原方案那样逐只 mootdx 增强 ROE——**ROE 改为随财报快照全市场一次到位**，财报三项新增指标共用同一份快照。财报数据报告期内基本不变，缓存 6–12h；东财只被分页拉一次，不做 5000+ 次逐只请求，规避封 IP。其余深度条件（一致预期/资金/技术/情绪）本期不做。

> 3. 未披露 / 数据源未覆盖 ≠ 不满足条件：开启「仅显示已披露财报」时，未披露行直接不进入结果集并单独计数展示；关闭时，未披露行照常展示，但**只要设置了任一财报区间条件，未披露行不参与命中**（缺值无法判断，不能算作满足）。
> 4. 四项指标的增减方向不构成买卖建议；同比仅表达「报告期 vs 上年同期」的客观变化。

## 五、后端接口设计

### 5.1 第一层（必做）

```
GET /api/screener/snapshot?markets=main,gem,star,bj
```

- 后端：一次拉起全市场代码表（`frontend/src/data/stock_codes.csv` 或服务端同源副本）→ 腾讯批量（分块 500，并行度但腾讯不封）→ 解析 88 字段 → 内存缓存（TTL 30–60s）→ 返回紧凑 JSON。
- 复用 `backend/astock.py` 现有 `get_prefix` / `_fetch_gtimg` / `_parse_gtimg` / `tencent_quote`（`astock.py:94`），**无需另起模块**。
- 返回体建议紧凑列式（减少体积，利于前端本地过滤）：

```jsonc
{
  "as_of": "2026-09-13T15:00:03+08:00",
  "count": 5483,
  "fields": ["code","name","price","change_pct","turnover_pct","vol_ratio","amplitude_pct",
             "pe_ttm","pb","mcap_yi","float_mcap_yi","amount_wan",
             "limit_up","limit_down","security_type","is_stale"],
  "rows": [["600519","贵州茅台",1275.16,-0.78,0.28,1.25,1.80,19.57,6.34,15940.54,15940.54,443084,1413.64,1156.62,"GP-A",false], ...]
}
```

- 体积估算：约 5500 行 × 16 字段，紧凑数组 JSON ≈ 1.2–1.7 MB；开启 `GZipMiddleware` 后 ≈ 300–400 KB，一次拉取可接受。
- 前端 `ScreenerTable` 用虚拟滚动（`@tanstack/react-virtual` 或轻量自实现）渲染，避免 5000 行 DOM。

### 5.2 第二层（全市场财报快照，新增）

```
GET /api/screener/financials
```

- 后端：按报告期调用一次东财业绩报表 `ak.stock_yjbb_em(date=YYYYMMDD)`（内部约 24 页，实测 ~7s、1.1 万行），只保留 6 位 A 股代码并映射四个字段：
  | 接口字段 | 本页字段 | 说明 |
  |---|---|---|
  | `营业总收入-同比增长` | `revenue_yoy` | 累计同比，% |
  | `净利润-同比增长` | `profit_yoy` | 累计同比，% |
  | `净资产收益率` | `roe` | 累计值，% |
  | `销售毛利率` | `gross_margin` | 累计值，% |
- 返回 `{period, as_of, covered, fields, rows}`：`period` 为报告期（如 `20260930`），`as_of` 为抓取时间，`covered` 为有效覆盖只数；`rows` 为 `[code, revenue_yoy, profit_yoy, roe, gross_margin]` 紧凑数组，缺值为 `null`（不填 0）。
- 期次选择：候选最近 4 个季度末（如 20260930 / 20260630 / 20260331 / 20251231），取「覆盖率 ≥ 30% 的最新一期」；若都未达阈值，取覆盖率最高的一期并在响应中带 `partial: true`，前端标题徽标追加「部分披露」。
- 缓存：进程内 6h（报告期内数据变化慢），失败保留上一次好数据并带 `stale: true`；冷启动失败返回 502，前端把财报卡置为「未获取」且禁用输入。
- 与 `/api/screener/snapshot` 并行请求；两者都完成后前端按 `code` merge。财报接口慢于行情时，先展示行情结果，财报返回后再补列（不阻塞首屏）。
- 原 `/api/screener/enrich?groups=roe` 在 ROE 迁入 L1.5 后可保留为兼容接口，但页面不再调用；后续如需单票财务明细可继续复用。

### 5.5 调用路径与 3 秒预算

数据源映射、调用时序、耗时拆解与降级策略详见独立文档 **[stock-screener-api-call-plan.md](stock-screener-api-call-plan.md)**。要点：

- 关键路径 = `§1.2 tencent_quote`（全市场分块 500 批量）；**财报走并行的 `stock_yjbb_em` 全市场快照（冷启动 ~7s，缓存后 <50ms），不阻塞行情首屏**；巨潮代码表后台刷新（可选）。
- 冷启动行情 1.9–2.4s、热缓存 <50ms、前端本地过滤 <50ms；财报首次约 7s，加载期间财报卡与四列显示占位/「—」，其余筛选与排序立即可用。
- 落地前需先修 `astock.py` 的 4 个既有问题：`get_prefix` 北交所 920 号段判定、`security_type`（字段 61）、`is_stale` 解析、腾讯分块。

## 六、交互与状态设计

### 6.1 过滤流程

采用**显式提交**：编辑条件不立即影响结果，点「开始筛选」才应用。

```
进入页面
  → 并行拉 /api/screener/snapshot 与 /api/screener/financials（各自内存缓存命中则秒回）
  → 行情与 L0 本地表按 code 合并（行业/地区/板块/上市日）
  → 财报快照按 code 合并四字段（revenue_yoy / profit_yoy / roe / gross_margin）
  → 按默认条件先展示一次（不等财报：未返回时财报条件保持禁用）

编辑条件（写入 draftConditions，当前结果不变）
  → 点「开始筛选」：draftConditions → appliedConditions，纯本地 useMemo 过滤并重算命中集（无网络请求）
  → 财报条件参与本地过滤；缺值行按 §4.2 口径排除并单独计数
  → 点「重置」：清空草稿与已生效条件，回到默认（排除僵尸=开、排除 ST=开、仅显示已披露=开）并立即重筛

排序 / 分页 / 列设置：纯前端；不再有 ROE 异步增强请求
```

### 6.2 关键状态

- `draftConditions`：编辑中的草稿条件，仅本地 state，点「开始筛选」前不影响结果。
- `appliedConditions`：已生效条件，驱动过滤；序列化后存 `localStorage`（键 `vr-screener-conditions-v3`），刷新/重进保留。
- `financials`：`{period, as_of, covered, partial, rows}` 或 `null`；`financialsStatus ∈ idle/loading/done/error/stale`，驱动财报卡禁用态与工具栏状态文案。
- `financialsMap`：`Map<code, 四字段>`，会话内按快照合并一次，不做逐只请求。
- `filterDirty`：草稿与已生效条件不一致时为真，「开始筛选」呈高亮可用；一致时可置灰提示无改动。
- `staleGuard`：请求竞态守卫 `runIdRef`，与 `StockData.tsx` 现有模式一致，旧响应不覆盖新结果。
- `snapshotAsOf`：快照时间戳，展示在工具栏；数据过旧（>N 分钟）时高亮提示，不静默。

### 6.3 行内动作（不含投资建议）

| 动作 | 行为 |
|------|------|
| 加入自选 | 调 `addCodes` 写入本地自选（复用 `lib/watchlist.ts`） |
| 查看个股 | 跳 `/stock-data?code=xxx`，个股数据页读取 `code` 参数并自动查询该股 |
| 导出 | 当前筛选结果导出 CSV（纯前端 Blob，字段与列设置一致） |

## 七、性能与防封

| 风险 | 措施 |
|------|------|
| 全市场快照体积大 | 后端 TTL 缓存 + GZip + 紧凑数组；前端虚拟滚动 |
| 腾讯限流（连续 5000+ 次返回空） | 只在刷新时拉取（默认 60s 内不重复请求），分块 500，不轮询 |
| 东财封 IP（实测 10 线程 45000 次封 20+ 小时） | 财报快照只做**一次全市场分页拉取**（约 24 页 / 7s）+ 6h 缓存，不逐只调用；后续扩展若需逐只东财接口，须对 ≤50 只候选集串行 `em_get`、每只间隔 ≥1s、复用会话 |
| 财报快照冷启动慢（~7s） | 与行情快照并行，不阻塞首屏；加载中财报卡显示「财报数据加载中…」并禁用输入，结果表四列显示占位「—」 |
| 页面卡顿 | 5000 行不一次性渲染；过滤用 `useMemo` + 预建索引（如按市场分桶），避免每次全量扫描；财报 map 只构建一次 |

## 八、降级与合规

### 8.1 降级策略（必须在 UI 出声）

- 快照接口失败：保留上一次好数据并标注「数据可能过期」，不展示空表冒充成功；无缓存则显示错误态 + 重试。
- 僵尸报价：`is_stale` 的行默认剔除，若用户关闭该过滤，行内加「停牌/废码」灰标。
- 财报快照失败：财报卡显示「财报数据未获取」+ 失败原因，四个区间控件禁用（`disabled`），结果表四列显示「—」；若存在上一次好数据，标注「数据可能过期（YYYY-MM-DD HH:mm）」并允许使用，不静默用旧值冒充实时；行情筛选与结果表其余功能不受影响。
- 财报部分披露（`partial=true`）：标题徽标追加「部分披露」，工具栏同步提示；「仅显示已披露财报」默认开启，避免未披露个股被误当「不满足条件」。
- 财报缺值：单只缺值行四列显示「—」并带 `title`（「该股此报告期未披露」/「财报源未覆盖」）；设置任一财报区间条件时缺值行不命中，并在工具栏显示「已排除 N 只无财报数据」。
- 北交所老号段：按 `SKILL.md` §1.2 提示，只信巨潮代码表的现行码，避免静默拿到另一只股票数据。

### 8.2 合规红线（对齐 `AGENTS.md` §0）

- 结果只含**数据、筛选条件、排序**，不含「买入/卖出/持有/目标价/止损」等任何动作建议。
- 情绪类维度（涨停、热榜、龙虎榜）统一标注「情绪参考，不进核心结论」。
- 一切派生比率/倍数（前瞻 PE、PEG、同比、占比、分位）经 `calc/` 计算，禁止前端心算或手搓公式。
- 不接入需要密钥的源（如 iwencai，§2.3），维持 Phase 0 零鉴权边界。

## 十、验收要点（自查清单）

1. 侧边栏「股票筛选」在「自选股」正下方，展开/折叠态均正常，激活态高亮。
2. 首屏只依赖 L1 快照即可完成「市场+行业+PE/PB+市值范围+换手+涨跌」全部筛选，本地交互无网络等待；财报快照并行加载，不阻塞首屏。
3. **「财报」卡片位于「行情」卡片正上方**，一行四列（营收同比 / 净利同比 / ROE / 毛利率），每列含区间输入与快捷 chips；「估值」卡片不再包含 ROE。
4. **财报四项筛选全部在本地完成**：任一区间条件生效后，未披露/缺值行不命中并单独计数；「仅显示已披露财报」开关默认开启且行为符合 §4.2 口径。
5. **报告期与口径可见**：财报卡标题、结果工具栏均显示报告期（如 `2026Q3`）与「累计口径」；部分披露时追加「部分披露」；不存在把累计值写成单季或 TTM 的文案。
6. 筛选区底部有「重置」「开始筛选」两个按钮：编辑只改草稿，点「开始筛选」才应用并滚动到结果，**不自动折叠筛选区**；「重置」清空并回到默认条件立即重筛。
7. 页面为上下布局：筛选区在上、结果列表在下，符合「简洁美观」排版规范（见 §3.4–§3.9）；≥1440 财报四列一行，<1024 为 2 列、<640 单列。
8. 快照时间戳、财报报告期/更新时间、数据层标识、降级原因在 UI 可见；失败不伪装成功、不用旧值冒充。
9. 结果表所有派生数字标注 `calculation_id`（或前端仅做展示、不做运算）；财报四项由后端快照直接提供，前端不做换算。
10. 全页无任何投资动作建议措辞；情绪类数据带「情绪参考」标注。
11. 导出的 CSV 与当前筛选结果、列设置一致，且包含可见的财报四列。
