# 多空辩论页（/debate）UI 设计

> 范围：旧版 Web 应用多空辩论页 `frontend/src/pages/Debate.tsx`（运行于 `http://localhost:8901/debate`）。
> 原则：页面只组织「多方 / 空方 / 中立主持」围绕**同一份客观数据**的发言，终点是「分歧点 + 验证清单」，**不给买卖结论**；所有事实数字由后端实时拉取，AI 只做组织与表达。
> 结构：页面定位（§一）→ 整体布局（§二）→ 子功能详解（§三）→ 交互时序与状态（§四）→ 数据与降级（§五）→ 合规边界（§六）→ 相关文件索引（§七）。
> 说明：布局与文案依据当前源码整理，非截图录入。

---

## 一、页面定位

- 路由 `/debate`，侧边栏「多空辩论」（`Swords` 图标，`Layout.tsx:28`）；内容区沿用 `Layout` 默认宽度 `mx-auto max-w-6xl px-6 py-6`。
- 输入 6 位 A 股代码 → 后端**先拉一份客观事实底稿**（不经 LLM），再让多个 AI 角色基于同一份底稿流式发言。
- 单列自上而下：页头 → 控制栏 → 角色发言区 → 空态引导 → 免责声明；无侧栏、无 Tab。
- 与「AI 交易 agent」框架的关键区别：**刻意不产出 trader / 买卖结论**，多视角本身就是产品。分析交由用户自己配置的模型完成（沿用「接入 AI」里的配置），本地不上传。

## 三、子功能详解

| 区块 | 子功能 | 展示内容与交互 | 布局 | 显示条件 |
|------|--------|----------------|------|----------|
| [A] | 页头 | 标题「多空辩论」+ 定调副标题（不给买卖结论） | 标题左 | 始终 |
| [B] | 控制栏 | 见下表 [B1]–[B5] | `flex flex-wrap items-end gap-3` | 始终 |
| [B1] | 代码输入 | 6 位数字（`replace(/\D/g,"").slice(0,6)`），回车即开始；运行中禁用 | 标签 + 输入框（`w-44` 等宽） | 始终 |
| [B2] | 辩论深度 | 下拉：`一轮 · 各自陈述` / `两轮 · 加交叉反驳` | 标签 + `select` | 始终 |
| [B3] | 主按钮 | 未跑：「▶ 开始辩论」；运行中：「⛔ 中止」（`AbortController.abort`） | 输入行尾部 | 始终 |
| [B4] | 存入沉淀 | 「💾 存入沉淀」，完成后出现；已存后禁用并显示「已存入沉淀」 | 主按钮右侧 | 辩论完成且未在跑 |
| [B5] | 开销提示 | 点下去前预告耗时 / 模型调用次数 / 上下文规模；强调拉底稿约 35 秒、走公开接口不耗 token，省额度可用本机 CLI 或中档模型 | 控制栏底部一行小字 | 未运行且无状态文本 |
| [B6] | 状态行 | `正在拉取客观事实底稿… L/T` → `底稿就绪，辩论开始` → `辩论完成` / `已中止` | 控制栏内一行 | 有状态文本 |
| [B7] | 错误行 | `⚠` + 文案（形如 `bull：生成失败…` 或配置/数据错误） | 控制栏内一行（destructive） | 有错误 |
| [B8] | 底稿进度 | 13 项抓取进度：每项 `✓`（成功）/ `○`（未取到）+ 小标题；下方「未取到：…（双方立论时不得臆测这部分）」警告 | `flex flex-wrap` 徽标 | 抓取开始后 |
| [C] | 角色发言区 | 每个角色一张描边卡：`Swords` 图标 + 标签 +（未完成时「生成中…」脉冲）；正文 `ReactMarkdown + remarkGfm` 流式渲染 | 单列 `space-y-4` | 有发言阶段 |
| [D] | 空态引导 | `Swords` 大图标 + 引导文案（先拉客观底稿、再互相质疑；产出「分歧点 + 验证清单」） | 居中卡片 | 无发言且未运行 |
| [E] | 免责声明 | 合规声明 | 页脚 | 始终 |

**对话深度 → 角色顺序**（`_stage_plan`）：

- 一轮（`rounds=1`）：多方研究员 → 空方研究员 → 中立主持。
- 两轮（`rounds=2`）：多方研究员 → 空方研究员 → 多方反驳 → 空方反驳 → 中立主持。

**「存入沉淀」内容**：把各段拼成 Markdown（`## 标签 + 正文`，`---` 分隔），`addNote("多空辩论", "多空辩论 · {code}", body)` 存进本地「研究记录」（`localStorage`，键 `vr-notes`），不上传。

## 四、交互时序与状态

### 4.1 事件流（NDJSON，`POST /api/debate`）

前端 `debateStream(code, rounds, handlers, signal)` 按行消费后端事件（`frontend/src/lib/agents.ts`）：

| 事件 `type` | 载荷 | 前端动作 |
|------|------|----------|
| `status` | `message` | 设置状态行 |
| `dossier_progress` | `title/ok/loaded/total` | 追加底稿进度徽标；状态行显示 `… L/T` |
| `dossier` | `sections` / `missing` | 记录缺口 `missing`；状态置「底稿就绪，辩论开始」 |
| `stage` | `stage` / `label` | 追加一张该角色的空卡（`done=false`） |
| `delta` | `stage` / `text` | 把增量文本追加到该角色卡 |
| `stage_done` | `stage` / `label` / `content` | 用全文覆盖该角色卡并置 `done=true` |
| `error` | `message` / `stage?` | 写入错误行（`stage` 存在时前缀角色 key） |
| `done` | `code` / `stages` | 收尾（前端置「辩论完成」） |

### 4.2 状态

- `running`：运行中禁用代码 / 深度输入，主按钮切换为「中止」。
- `finished` = 有阶段且全部 `done` → 出现「存入沉淀」。
- `reset()`：每次「开始辩论」前清空状态、进度、缺口、发言、错误、已存标记。
- **中止**：`AbortController.abort()` → 捕获 `AbortError` → 状态置「已中止」，已产生的发言保留。
- **必须配置 AI**：未在「接入 AI」配置模型时，`loadLlm()` 为空 → 抛 `ApiError(400, "尚未接入 AI，请先在「接入 AI」里配置")`，错误行展示。

## 五、数据与降级

### 5.1 客观事实底稿（不经 LLM，后端固定清单）

后端 `collect_dossier` 逐项拉取并 yield 进度；**任何单项失败都不阻断**，缺项进 `missing` 列表。清单（`backend/debate.py #_DOSSIER_SPEC`）：

| 小标题 | 工具 | 并行 | 空结果语义 |
|--------|------|:----:|-----------|
| 实时行情 | `query_quote` | ✓ | 空=异常（计入缺口） |
| 估值与一致预期 | `query_valuation` | ✗（串行） | 空=异常 |
| 估值历史分位 | `query_valuation_percentile` | ✓ | 空=异常 |
| 最新财报关键指标 | `query_financials` | ✓ | 空=异常 |
| 近 60 日价格走势 | `query_kline`（count=60） | ✓ | 空=异常 |
| 资金流向 | `query_fund_flow`（days=5） | ✗（串行） | 空=异常 |
| 融资融券 | `query_margin` | ✗（串行） | 空可能是真实情况 |
| 股东户数 | `query_holders` | ✗（串行） | 空可能是真实情况 |
| 近期公告 | `query_announcements` | ✓ | 空可能是真实情况 |
| 限售解禁 | `query_lockup` | ✗（串行） | 空可能是真实情况 |
| 板块与概念归属 | `query_concepts` | ✗（串行） | 空=异常 |
| 近期研报 | `query_reports` | ✓ | 空可能是真实情况 |
| 近期新闻 | `query_news` | ✓ | 空可能是真实情况 |

- **并行/串行的取舍**：走东财 `em_get` 的（估值 / 资金流 / 两融 / 股东户数 / 解禁 / 板块）一律**串行**以尊重防封节流；走腾讯 / 百度 / 同花顺等的可并行（`_PARALLEL_WORKERS=4`）。
- **空 vs 缺失**：「空可能是真实情况」的项为空时进底稿并写明「未取到任何记录：可能确实没有此类事件，也可能是该数据源暂时不可用」，**不计缺口**；其余为空计入 `missing`。
- **单项注入上限** `_SECTION_CAP=1800` 字，防止某项撑爆底稿。
- **致命失败**：若整份底稿没有任何一条真实数据（全是「无记录」说明）→ 后端 `error`「未能取到任何客观数据，无法开始辩论」，不发角色发言。
- **底稿可读性**：最终按清单原始顺序还原 `sections`，保证每次底稿结构稳定。

### 5.2 底稿如何进模型

- 底稿渲染成纯文本（`## 小标题（来源工具 xxx）` + JSON/说明），**始终放在每个角色的 system 消息里**；已产生的发言作为 user 上下文按角色裁剪（首轮多方不看任何人、空方只看多方；反驳轮看对方论述）。
- 角色提示词内嵌「共同规则」：只能用底稿数据立论、无数据支撑要标注、不预测涨跌 / 价位 / 时机 / 目标价 / 仓位（见 §六）。

### 5.3 前端失败/空态

- 底稿抓取：逐项徽标（`✓/○`）+ 缺口警告（`text-warning`）「未取到：…（双方立论时不得臆测这部分）」。
- 配置/取数错误：控制栏错误行（`AlertTriangle`）。
- 单角色生成失败：后端发 `error`（带该角色 stage）后仍补发 `stage_done` 占位，保证该卡不悬空、不无限「生成中…」。
- 未开始时用空态卡引导，不留空白。

## 六、合规边界（为什么没有买卖结论）

- 产物固定为「多方怎么说 / 空方怎么说 / 双方真正分歧在哪 / 判定分歧需要什么证据」，**不裁决谁对、不给操作建议**。
- 共同规则与主持提示词硬性禁止：预测涨跌与价位、给买卖时机 / 目标价 / 仓位建议、承诺收益；主持被要求「绝对不要给出结论倾向或更认同哪一方」。
- 底稿数字全部来自公开接口实时拉取，多空双方拿到**同一份**数据，谁也不能靠编数字赢；缺口在页面上明示。
- 页面底部 `Disclaimer` 兜底：只呈现事实，不推荐、不预测、不构成投资建议；分析方向由用户自己的 AI 给出。
- 辩论内容与底稿均可由用户手动「存入沉淀」，仅存本地，不上传。
